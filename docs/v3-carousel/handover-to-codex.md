## 0. 一句话现状

V3 是「智能分页 + 受控随机排版」的 IG 连续图原型：**分页规则**（每页 2–4 张、不丢图）+
**几何排版**（固定种子可复现、内容区永不碰撞）+ **三条材质轴**（边框 / 边缘 / 胶带）+
**按风格的背景族** + **排版层装饰第一档**（页脚条 / micro-label / 细线）。导出为 1080 宽的逐页 PNG。

已上线：<https://cfyofjackie.github.io/albummm/?prototype=carousel-smart&variant=gallery>
（推 `main` 即自动部署，见 §7）

## 2. 代码地图（V3）

```
src/v3-carousel/
├─ layout/
│  ├─ carouselSmartPagination.js      纯分页：pageCountPlan / paginatePhotos。改分页规则只在这里
│  ├─ carouselPlacement.js            ★ 几何核心：页面规格、尺寸边界、材质轴、放置、碰撞、导出轮廓
│  ├─ pageDecor.js                    排版层装饰：页脚内容、micro-label 页数与矩形、label 文字
│  └─ paperBackgrounds.js             背景族：每个风格 2–4 个背景（纯 CSS 值 + 色板数据）
└─ prototypes/
   ├─ CarouselScatterPrototype.jsx    ★ 主组件（所有 UI、导出、卡片渲染都在这里）
   ├─ CarouselScatterPrototype.css    预览 + 导出的样式（纸面、卡片、材质、装饰）
   ├─ CarouselMastersPrototype.*      历史：卡片/纸张的公共样式（.carousel-master__*）
   ├─ CarouselSmartPrototype.jsx      249 字节的包装，指向 Scatter
   └─ CarouselRhythmPrototype.jsx     同上（节奏模式）
```

`layout/` 下的模块是**纯函数 + 可测**的，组件只做「把数据变成 DOM」和「把几何层的值写成 CSS 变量」。
**新增任何视觉决定，先把数值放进 `layout/`，再让组件渲染它** —— 这是这个项目一直以来的做法，
也是唯一能保证「预览 == 导出」和「可回归测试」的做法。

### 关键数据流

```
planSmartStory(photos, seed, style, format, material)   ← 唯一的排版入口（纯函数）
  ├─ 分页：paginatePhotos → 每页 2–4 张
  ├─ 每页：placeFrameBest → 多轮候选 + 尺寸阶梯缩放（FITTING_SCALES），选「完整放下且拒绝最少」的一轮
  ├─ 每张卡片带：x/y/w/h/rotate + mat（边框像素，渲染与碰撞共用同一份）+ tape/label/tear 标记
  └─ 页级：pagePlan / frame.fittingScale / contentCollisions（必须为 0）
```

导出：`html-to-image` 的 `toBlob`，在一个 **1080 宽**的离屏画布上逐页截图（每页一个 PNG，
背景用 `background-position-x` 平移取本页那一格），文件名 `albummm-v3-<format>-<NN>.png`。

## 3. 现在的设计系统（四条轴 + 装饰）

### 3.1 风格（三种，只改纸面气质与几何参数，不改分页）

| id | 名称 | 几何特征（`STYLE_LAYOUTS`） |
| --- | --- | --- |
| `gallery` | 安静纸面 | 旋转 0°、尺度最平、**不叠放**、最安静 |
| `muse` | editorial | 旋转 ±0.2°、轻微相叠（`overlapUse .5`）、低饱和色带 |
| `weekend` | 节奏更快 | 旋转 ±2.6°、尺度变化最快、可叠 2 处、网格/牛皮纸 |

**硬要求：三种风格必须可以被分辨**，这有专门的测试（旋转分档 / 尺度对比分档 / 轻叠差异）。
历史教训（`validation-log.md` §11）：曾经因为 recipe 遮蔽了 style 参数，三种风格实测只差 0.45°/1.8° 旋转，
尺寸差 0.03% —— 所以「风格参数是死代码」是这个项目真实发生过的 bug。

### 3.2 页面规格（`PAGE_FORMATS`）

`4x5`（1080×1350，默认）、`3x4`（1080×1440）、`4x3`（1080×810）。
每个规格都**按自己的比例重新构图**（不是把一种构图缩放过去），分页结果与规格无关。

### 3.3 材质 = 三条独立轴（`materialOf({ border, edge, tape })`）

| 轴 | 取值 | 当前数值 | 必须遵守 |
| --- | --- | --- | --- |
| **边框** | 无 / **拍立得** | 基础白边 3–5px；拍立得 = 左右/上 ×5、下边 ×12（25–60px） | 下边增厚按**卡片短边封顶 8%**（超宽图不被套厚下巴） |
| **边缘** | 直边 / **毛边** | 撕深 = 卡片短边 × 8.5%，硬上限 **12%**；每张照片**只撕一条边**（竖图撕左右、横图撕上下）；**每页只挑一张**（面积最大） | 撕口**允许裁掉照片边缘**（产品确认的唯一裁切例外）；撕深计算在 `tornContours` |
| **胶带** | 无 / **和纸胶带** | 厚度 = 页宽 × 1.9%（≈20px@1080），长度 = 卡片宽 × 44% | 条数 = **页内照片数 − 1**（至少 1）；**压在相纸外缘上**（一半在白边、一半越出）；矩形并进安全盒 |

三条轴的关键设计：**白边与胶带是几何参数**（进 `sizeFor / innerBox / 碰撞判定`，`card.mat` 存值），
**边缘是渲染参数**（只裁轮廓，不改尺寸与碰撞）。边框厚度一变，同一页放得下的东西就变了。

### 3.4 背景 = 风格内部的一组纸面（`paperBackgrounds.js`）

| 风格 | 背景组 |
| --- | --- |
| Gallery | 暖白纸 / 雾灰 / 冷白 / **泛黄纸**（折痕 + 粗纤维噪声） |
| Muse | 奶油 / 灰粉 / 雾蓝 / 鼠尾草（横向色带，各 4 个色阶） |
| Weekend | 牛皮纸 / 米色 / 灰绿（网格 + 颗粒 + 左下小色点） |

- 纯 CSS：底色 + **SVG 噪声颗粒**（`feTurbulence` + `stitchTiles='stitch'`，无缝）+ 网格/色带/折痕 + 可选小色点。
- 只换 `--paper-color / --paper-image / --paper-size / --paper-blend` 四个变量（预览与导出共用）。
- 颜色对比**按面积分配**：大面积（底色/全幅渐变）彩度 ≤ .22、明度 ≥ .45；小面积（网格线/色带/色点）
  彩度 ≤ .55、明度 ≥ .20。判据是**彩度**（max−min 通道差），不是 HSL 饱和度。
- **必须可平铺**：逐页导出靠 `background-position-x` 平移取景，不可平铺的整幅大图会露出接缝。

### 3.5 排版层装饰（第一档，已实现）

- **页脚条**：细线 + 左「`01 / 05`」（EB Garamond 衬线、tabular 数字）+ 右「`VOL. 01`」
  （Inter、全大写、字距 .22em）。开关在状态栏（文案仍是「页码」，实际控制整条页脚）。
- **micro-label**：一组 **2–4 处**，首尾页优先（5 页 → 第 1/3/5 页）；文字 = 照片的**真实序号**
  （`FRAME 01`）；贴在卡片**下方**（不压照片），**矩形并进碰撞安全盒**（放置时预留）。
- **细线**：页脚分隔线 + micro-label 前的短刻度。
- **字体自托管**：`@fontsource/eb-garamond` + `@fontsource/inter`（OFL，各两个字重、latin 子集，
  每个 woff2 ≈23KB）。**不得用 CDN**；导出前必须 `await document.fonts.ready`。
- **装饰尺寸一律用 `cqw`**（页宽的 1%，靠 `.scatter-frame` 的 `container-type: inline-size`），
  不得用 `px` —— 预览页宽 216–335px、导出 1080px，用 px 会让两边比例不一致（曾经如此）。

## 4. 硬规矩（改动前必读，违反了要回退）

完整版在 `development-guardrails.md`，这里是**必须记住的实质**：

1. **分页规则不得改**（除非产品明确批准）：每页 2–4 张、2 张页占比最高、4 张最多一页、
   **不丢图**（`pagePlan` 与照片总数守恒，有测试）。
2. **尺寸边界不得改**：内容短边 ≥ 页面短边的 20%（竖版）/ 15%（横版）作为**优先**下限，
   内容宽 ≤ 80%、高 ≤ 78%。整页放不下时按 `FITTING_SCALES` **整页等比缩放**（下限 0.48），
   不靠裁剪、不靠丢图。
3. **照片内容区永不碰撞**（有测试，含旋转外扩与材质占位）。
4. **不拉伸照片**；不因排不满而裁切。**唯一例外**：毛边材质允许撕掉照片边缘（上限短边 12%）。
5. **风格差异只能通过几何与纸面参数表达**，且三种风格**必须可分辨**（有测试）。
6. **材质必须通过 `layout/` 的参数进入几何层**，禁止只在 CSS 里加厚边框/贴胶带。
7. **背景属于风格**，不得跨风格乱配；不得高饱和/深色；必须可平铺。
8. **装饰顺序：背景 → 排版层（细线/色带/日期位）→ 贴纸式（最后，需批准）**。
   贴纸 / 手写 / 纸张碎片未获批准不得加入（与 `direction.md` §3 的「避免落入 scrapbook」一致）。
9. **预览必须等于导出**：所有视觉数值走几何层 → CSS 变量；尺寸用 `%` 或 `cqw`，不用 px。
10. 改动风格/材质参数后，若「三种风格可分辨」「八种材质组合硬边界」这些测试失败，
    说明差异被改没了或边界被破坏，**先修回来再谈别的**。

## 5. 设计问题清单（★ 这是交给你的主要部分）

### 5.1 已决定（不要再翻案，需要改要先说服产品负责人）

- 导出规格：4:5 + 3:4 + 4:3 三套（默认 4:5）。
- 白边基础范围 2–5px；20% 是**优先**下限而不是硬边界（整页缩放可以突破）。
- 材质三条独立轴；胶带条数 = 页内照片数 − 1；毛边每页一张、只撕一条边。
- 背景按风格各配 2–4 个；颜色对比按面积分配。
- 装饰走「用排版做装饰」路线（依据：`reference/carousel` 11 张参考图的清点，见 §6）。
- 字体自托管、装饰尺寸用 cqw。

## 6. 设计依据：参考图清点（重要）

### 6.1 `reference/carousel/`（11 张，已全部清点）

两类：**模板商品图**（before/after、`SLIDE 1-5` 条状展示、Canva 模板页）与**真正在用的设计**
（白底 editorial、暗底 olive、浅蓝底、婚照条状）。装饰出现频率：

| 装饰 | 出现 | 每组用量 |
| --- | --- | --- |
| 序号 / 页码（`.01`、`03/`、`PAGE 01/05`、`SLIDE TWO`） | 几乎全部 | 每页一处，极小 + 大字距 |
| micro-label（极小全大写） | 白底 / 暗底 editorial | 2–4 处 |
| 细线（页脚线、标题下短横线、标签短刻度） | 多数 | 2–4 处 |
| 衬线大字压在照片/色块上 | olive editorial | 1–2 处 |
| **竖排文字** | olive editorial | 1 处 |
| 段落文字块 | 白底 editorial；暗底 1 处 | 1–2 处 |
| 色块 / 色带面板 | 白底、olive | 每页 ≤1 处 |
| 手写花体 | 浅蓝底那组 | 1 处 |
| **贴纸 / 胶带 / 撕纸** | **几乎没有**（胶带只作为"贴照片"的功能出现） | — |

**结论：参考图非常克制，而且克制的方式是「用排版做装饰」。** 这是第一档装饰（页脚条 + micro-label +
细线）的直接依据，也是第三档（贴纸）建议暂缓的依据。

### 6.2 更早的两张参考（对话中提供，不在仓库里）

- 「散落的回忆」：宽白边相纸（拍立得）+ **毛边** + 半透明和纸胶带 + 红爱心/`LOVE`/手绘箭头 + 轻微叠放。
- 第二张同类：有**白边相纸+胶带**、**无白边直接撕边**、**右下角被撕掉一大块**、手写长句横跨画面。
  → 这两张是「毛边要啃照片本体」「胶带压在相纸外缘」「一组 1–2 处贴纸」的直接来源。

## 7. 工作约定（**务必遵守，否则会污染别的会话**）

- **提交前缀 `V3:`**，一个决定一个提交，提交信息写清「为什么」和实测数据。
- **只 stage 这些路径**：
  - `src/v3-carousel/**`
  - `docs/v3-carousel/**`
  - 需要新依赖时才加 `package.json` / `package-lock.json`（本次加了 `@fontsource/eb-garamond`、`@fontsource/inter`）
- **不要碰别的会话的未提交文件**：`src/v4-gallery/**`、`SLC.md`、`note.md`、`reference/**`、`风格和样式.md`、
  `src/App.jsx`（除非确实要加路由）。`git status` 里长期有它们的 ` M`，**不要顺手提交**。
- 部署：推 `main` → GitHub Actions（`.github/workflows/deploy.yml`）自动构建发布到

## 8. 已知的坑（都是真踩过的，避免重复）

### 导出 / 渲染

1. **被截图的节点不能带 `position: fixed` 或离屏偏移** —— html-to-image 会连定位一起克隆，
   `foreignObject` 里会画到画布外（曾经导出全白）。偏移放在外层 `.scatter-export-holder`。
2. **导出画布里的页面必须有显式高度**（`.scatter-export .carousel-master__frame { height: 100% }`）：
   卡片都是绝对定位、不撑高度，不给高度 + `overflow: hidden` 会导出成空白页。
3. **切页要 `flushSync`**，否则循环里会截到上一页（曾经 5 页导出成 5 张一模一样的图）。
4. **绝对定位的相纸层会盖住静态 `<img>`**（照片整张消失）→ `img` 需要 `position: relative; z-index: 1`，
   卡片自身的背景/阴影要挪到被裁切的相纸层上。
5. **`clip-path` 的 polygon 里出现 `NaN` 会被浏览器整条丢掉**（静默失败，`getComputedStyle` 返回 `none`）。
   成因：几何函数按页面坐标算，而组件只传了 `{w,h,mat}`。现在轮廓用**元素自身坐标系**，
   并有测试断言 polygon 不含 NaN。
6. **组件里残留同名本地函数会遮蔽模块版本** —— 改了模块但画面没变，就是这种。撕口计算当时复现过。
7. **背景层的 `size` / `blend` 必须与图逐条对齐**：网格是两条渐变，只给一条 size 会让后面所有层错位
   （表现为"网格发灰、颗粒几乎看不见"）。现在每个层工厂返回对齐的三元组，并有测试断言层数一致。
8. **胶带高度要换算单位**：`thickness` 是页宽单位，而 CSS `height: %` 相对**卡片高度**；
   漏了这步胶带只有设计厚度的 40%（一直细得像根线）。
9. **`min-height` 会盖过几何比例**：桌面预览页宽只有 ~216px，`min-height: 6px` 让预览与导出的胶带不一样。已删。
10. **装饰用 px 会让预览与导出比例不一致**（差 5 倍）→ 全部改 `cqw`。
11. **CSS 锚点插入前先确认锚点唯一**：我曾把 `.scatter-export[data-scatter-page="4"] .scatter-frame`
    误并进新的选择器列表，导致 Muse 导出页 2/4 的装饰失效。

### 环境 / 工具

12. **PowerShell 读写文本会破坏 UTF-8**（`Get-Content | Set-Content` 会把中文变成乱码）：
    用文件编辑工具，或用 `[System.IO.File]::ReadAllText/WriteAllText`。`Set-Content -Encoding UTF8` 也会出问题。
13. **别把下载/临时文件放进仓库**：Vite 的文件监听会因 `.crdownload` 之类的锁文件直接**崩掉开发服**（EBUSY）。
    临时脚本与产物放 `$env:TEMP`。
14. **开发服会自己挂**（基本都发生在我跑 `npm run build` 前后），重跑前先确认端口在听：
    `Get-NetTCPConnection -State Listen -LocalPort 5175`。可以考虑在 `vite.config.js` 里忽略 `dist/`、`.tmp*/`。
15. **vitest 默认超时 5s**：跨全部格式 × 全部种子的重测试要显式加超时（`}, 30000)`），否则偶发失败。
16. **测试里不要跨页比较**：每页是各自的画布，跨页的"重叠"不是真重叠（我因此写错过一条测试）。
17. `gh run watch` 之后 `gh run list` 可能还是 `queued`，部署要等 40–60s 再验。

## 9. 验证方式（这个项目要求「数值对 + 画面也对」）

**最低要求**：`npx vitest run src/v3-carousel` 全绿 + `npm run build` 通过。

**但数值全绿不等于画面对**（上面第 4、5、6、7、8 条都是测试全绿但画面错）。所以视觉改动必须：

1. 起开发服，用无头 Chrome + CDP 截图（本项目没装 Playwright，历史上都是手写 CDP 脚本：
   `Page.navigate` / `Runtime.evaluate` / `Page.captureScreenshot` / `Browser.setDownloadBehavior`）。
2. **点一次「导出 4:5」，把导出的 PNG 打开看**（1:1 的 1080×1350），而不是只看预览。
3. 需要真机验证时，用 LAN 地址（页宽约 335px，最接近 IG 的观看条件）。
4. 改了线上路径后，用 CDP 直接打开 Pages 地址跑一遍（不要只 grep 产物字符串）。
