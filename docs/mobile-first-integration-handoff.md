# Albummm 第一轮整合与手机端移植修改文档

## 1. 本轮目标

把目前分散的 V3、V5 原型整理成**一个面向手机使用的 Web 产品**：用户从统一首页选择作品类型，再进入对应的独立创作页面。本轮重点是产品入口、项目结构和手机端呈现，不改两种作品的内容规则。

当前没有确定哪个方向是主功能。V3 与 V5 在首页平等呈现，后续分别邀请用户体验，再根据反馈决定产品重心。

## 2. 两种作品类型

| 首页选项 | 对应版本 | 成品与体验 |
| --- | --- | --- |
| 多页故事 | V3 `carousel-smart` | 一组可连续浏览、逐页导出的页面。 |
| 单张拼贴 | V5 `v5-reference-layout` | 把多张照片排成一张拼贴作品；现有点图进入高清场景的交互保留。 |

“多图拼接”就是 V5，不是第三种功能。正式界面使用用户能理解的名称，版本号仅用于开发与文档。

## 3. 页面整合

1. 默认打开产品首页，不再默认进入 V1。首页提供上述两个入口，说明每种类型会得到什么成品，并能直接进入创作。
2. V3、V5 各有独立的页面、交互状态、样式和排版引擎。页面整合不等于把两套编辑控件塞进同一屏，也不要求改写为一个通用排版引擎。
3. 两个创作页都能清楚返回首页。统一产品名称、基础导航和页面外层的视觉语言；作品画面与各自的创作控件可以保留不同气质。
4. 正式入口应有稳定、可分享的地址。现有 `?prototype=` 链接可以作为开发或兼容入口，但不应是普通用户选择功能的方式。
5. 路由切换时只加载当前需要的创作页，避免首页同时加载所有历史原型、字体和大图素材。

建议的信息结构：

```text
首页
├── 多页故事 → V3 创作页
└── 单张拼贴 → V5 创作页
```

## 4. 项目精简

精简目标是让**当前产品代码、历史实验和参考素材分得清楚**，并缩小正式页面需要加载的内容。

1. 将 V3 主候选与 V5 标为当前活跃功能。V1、V2、V4 及 V3 的其他对照原型不再出现在正式首页或正式构建的默认加载路径中。
2. 检查并移除不再被活跃功能使用的入口、导入、样式和依赖。共享目录只保留确实由两种功能共用的照片处理等能力，不为了“统一”而合并各自的排版代码。
3. 整理目录和文档：让活跃功能的位置一致、易找；更新过时的版本地图与启动说明，写明正式入口和实验入口。
4. 历史代码可以归档或在确认无依赖后删除，但要先列出拟处理清单，确认其用途和 Git 状态。仓库目前有未提交改动，不能把用户正在进行的 V4 等实验当作废弃文件直接清理。
5. `reference/` 是素材参考，不在本轮审查和清理范围。`check/`、`dist/`、`node_modules/` 等生成物或本机目录按现有忽略规则处理，不纳入产品源码。

## 5. 手机优先的页面适配

以手机竖屏为主要设计和验收对象。不要把桌面页面等比缩成一个居中的“手机长条”，也不要在手机视口两侧留下黑边或固定的大面积空白。页面外层应使用实际可用视口宽度；作品本身保持规定比例，不得为铺满屏幕而拉伸照片或画布。

### 共通要求

- 首页和两种创作页在常见手机宽度下自然排版；主要按钮、提示和作品预览无需捏合缩放即可阅读与操作。
- 正常页面不出现意外的整页横向滚动。V3 作品序列自身的横向滑动是预期交互，必须与页面滚动区分清楚。
- 顶部、底部操作区考虑刘海、圆角和系统手势区域；弹层、按钮和提示不得被遮挡。
- 关键操作不能依赖鼠标悬停。触摸区域、文字和控件间距要适合手指操作。
- 加载、空状态、文件选择失败等状态在窄屏上保持可读，不能因布局变化导致操作消失。

### V3 页面

- 手机端保持“一次重点看一页”的横向浏览方式，不把整组页面压成桌面上那条很窄的长带。
- 重新安排页面标题、上传、换排法、预览、风格与导出操作的层级。现有种子、碰撞等技术指标可留在开发视图，不占正式手机界面的首屏。
- 页面规格、风格、材质等现有功能仍可访问，但不要求所有开关在首屏同时出现。

### V5 页面

- 4:3 拼贴画布按可用宽度等比显示，不能因容器宽度、固定高度或 `overflow` 被意外裁掉。
- 标题、上传按钮、边框和装饰选项在窄屏上合理换行；作品应尽早进入视线，不被过高的说明区域推到很远的下方。
- 保留现有高清查看、关闭和导出能力，检查其在手机视口中是否被安全区域、工具栏或横竖屏变化遮挡。

## 6. 排版设计原则

这里要区分**产品页面布局**与**作品内部排版**：

- 产品页面布局从手机尺寸出发，适应不同手机宽度和高度。优先用弹性宽度、内容驱动高度和必要的断点处理窄屏，不依赖某一款手机的固定像素尺寸。
- V3 的单页画幅、V5 的单张画布仍保持各自的作品比例。响应式只改变它们在屏幕上的显示尺寸和周围控件布局，不改变照片比例、排版坐标或导出规格。
- 本轮不以桌面端视觉一致性为验收目标。桌面浏览器至少能打开和完成基本操作，但无需为桌面单独设计另一套完整体验。

## 7. 本轮明确不做

- 不改 V3 的智能分页、风格、构图、照片数量规则或导出内容。
- 不改 V5 的十图布局规则、照片比例准入、装饰逻辑或焦点场景内容。
- 不新增作品类型、自由编辑器、登录、云端同步或原生 iOS 工程。
- 不以此次整合为理由重写 React/Vite 技术栈。

如果手机适配暴露出排版引擎本身的问题，请记录为下一轮任务；本轮只处理显示容器与交互布局，并保持原有作品生成结果。

## 8. 建议实施顺序

1. 记录当前 V3、V5 的可运行链接和基线截图，确认现有测试结果。
2. 建立统一首页与两条独立的正式创作入口，保留必要的旧链接兼容。
3. 清理正式入口的历史原型导入，整理活跃目录和说明文档；历史文件按第 4 节保护规则处理。
4. 按手机优先原则调整首页、V3、V5 的页面外层与控件布局。
5. 在真实手机和浏览器窄屏下检查完整流程，修复遮挡、横向溢出和触控问题。

## 9. 验收标准

- 默认地址打开统一首页，首页只有“多页故事”和“单张拼贴”两个作品入口；都能进入、返回并通过链接直接打开。
- 在约 320、375、390、430 CSS 像素宽的手机视口检查首页及两种创作页：没有黑色侧边、整页意外横向滚动、内容压扁或主要操作被挡住。重点用 iPhone Safari 真机复核；Android 浏览器做基础检查。
- V3 可以完成现有的选照片、换排法、横向逐页查看和导出；V5 可以完成现有的选照片、切换边框/装饰、查看高清场景和导出。手机上无需鼠标悬停即可操作。
- V3/V5 的作品比例、排版结果及导出结果保持原有规则。现有 V3/V5 测试通过，生产构建成功。
- 正式首页不加载历史版本的主要代码与大图素材；项目文档能明确指出当前活跃功能、历史实验和正式入口。

## 10. 当前代码提示

- `src/App.jsx` 目前默认进入 V1，且静态导入所有版本和原型；这是首页整合与精简的主要入口。
- `src/v3-carousel/prototypes/CarouselScatterPrototype.jsx` 是 V3 主界面；`CarouselSmartPrototype.jsx` 是其当前主候选包装层。V3 手机端已有横向吸附布局，调整时应保留。
- `SLC/V5/V5CollagePrototype.jsx` 是 V5 页面；`SLC/V5/v5.css` 当前主要只有一个窄屏媒体查询。
- `src/index.css` 是全局样式。处理黑边和宽度问题时应先实测浏览器与具体页面，定位来源，再改相应容器；不要用全局裁切掩盖溢出。
- `vite.config.js` 当前为 GitHub Pages 的 `/albummm/` 子路径设置构建 base。改正式路由时检查本地、部署站点和直接刷新子页面的可用性。

这份文档是第一轮修改范围。完成后再讨论 V3/V5 各自的功能与作品内容优化，以及是否进入 iOS 原生容器阶段。
